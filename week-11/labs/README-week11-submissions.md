# Week 11 Submissions Guide

This guide lives in `week-11/labs/`. It explains how to move your six Cloud Heights Identity Center reports into your own GitHub portfolio and record them in the Lab Submission Tracker. For the week overview, see the [Week 11 root README](../README-week11-root.md).

## Where to Complete the Labs

Read the Week 11 instruction guides in the Lab Portal. Complete all six interactive labs in the **Cloud Heights Identity Center**: https://capstone.cybervisionariesinstitute.org/cyberfoundations/week-11. Follow its **Current Mission** panel for the exact steps, and do not reset between labs unless it tells you to. Download each Markdown report there, upload it to your own GitHub portfolio, then submit that GitHub file URL in the Lab Submission Tracker.

The Capstone site **requires you to sign in** with either your username/email or your Google account. Week 11 saves your IAM investigation, evidence, and Case File **under your individual student account**, so you can stop, return later, and continue where you left off. Answer checks happen privately on the course side — students do not see an answer key.

[**Open Week 11 Capstone Lab**](https://capstone.cybervisionariesinstitute.org/cyberfoundations/week-11)

> **Why do Weeks 1–10 look different?** Earlier Capstone activities are open because they do not save individual student work inside the Capstone site. Weeks 11 and 12 use student-specific saved work, so sign-in is required.

## Downloading Your Work

- **Download This Lab** gives you the individual Markdown report for the lab you are on. Use it lab by lab.
- **Download & GitHub** gives you the full Week 11 ZIP: all six lab reports plus an evidence folder with the supporting evidence the simulator captured.
- A download marked **DRAFT** means the lab is not finished yet. The download includes a **missing-items list** telling you exactly what is still incomplete. Finish those items in the simulator, then download again.

**Downloading is not submission.** A file on your computer is not in your portfolio and is not in the tracker.

## Step by Step: Upload a Report to GitHub

1. In the Cloud Heights Identity Center, use **Download This Lab** for the lab you finished.
2. Open **your own** CyberFoundations portfolio repository on GitHub — not the institute's template repository.
3. Open the `week-11` folder, then the `labs` folder.
4. Select **Add file > Upload files** and choose the downloaded report (for example `lab-01-identity-directory.md`).
5. Check the filename and that the destination is `week-11/labs/`.
6. Enter a meaningful commit message, such as `Add Week 11 Lab 01 report`, and select **Commit changes**. Committing means saving the file in your repository.
7. Open the committed file on GitHub and confirm it opens and contains your work — your name and your latest answers.
8. In the Lab Submission Tracker (https://labsubmission.cybervisionariesinstitute.org), paste the GitHub **file URL** into the submission for that lab.

Repeat these steps for each of the six labs. **One lab submission does not submit another** — each lab needs its own tracker entry with its own file URL.

## Using the Complete ZIP

If you used **Download & GitHub**, unzip the download, then upload the six lab reports to `week-11/labs/` as above. The ZIP's evidence folder is supporting material — keep it with your Week 11 files. You will draw on the Lab 06 case file and its evidence again in **Week 12**, when you write your Technical Incident Report + Executive Summary.

## If `week-11/labs/` Does Not Exist Yet

If you already saved this guide or another file into `week-11/labs/`, the folder exists — just use it. Only if the folder is missing:

1. From your repository's main page, select **Add file > Create new file**.
2. Type `week-11/labs/README.md` as the name. Each `/` creates a folder.
3. Add a short heading such as `# Week 11 Lab Reports` and select **Commit changes**.
4. Open `week-11/labs` and upload your report as above.

Never replace an existing `README.md`. That small helper file only creates the folder; it is different from this guide, `README-week11-submissions.md`.

## Revising a Report

1. Update your work in the simulator and download a fresh report.
2. If your browser renamed it (for example `lab-01-identity-directory (1).md`), rename it back to the original name.
3. Upload it to the same `week-11/labs/` folder, confirm GitHub shows you are updating the intended file, then commit.
4. Reopen the file and check your latest answers.
5. Follow the tracker's existing resubmission process for that lab, as shown in the tracker or by your instructor.

Do not delete other files or folders in your repository.

## Supporting Files (Notes and Reflection)

Your Week 11 [notes](../notes.md) and [reflection](../reflection.md) are completed in the Lab Portal. Use **Save Progress** there, and the portal's existing **Submit to GitHub** option to place them at `week-11/notes.md` and `week-11/reflection.md` in your portfolio. They are supporting work: they do not replace or count as any lab tracker submission.
